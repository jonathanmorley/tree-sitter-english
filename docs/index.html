What is exact here, and what is approximate?
  • Exact: the tagger (EWT test 92.1%), chunker, and lint rules are the same Rust code and weights as the native pipeline, including beam re-decode and all correction rules.
  • Approximate: sentence splits (naive .?! runs — Mr. mis-splits) and word tokens (whitespace/punctuation). The native grammar owns segmentation; the browser does not ship the C parser.
  • Native-only: clause-complexity, passive voice, and nominalization rules need grammar counts or parser weights.

What it is

A pipeline of narrow layers over English prose. Text flows one way:

text → grammar+scanner → tree → typed AST → words
     → POS tagger → (word, tag) → chunker → phrases
     → dependency parser → heads+labels → lint → findings
  • Grammar marks block structure only: paragraphs, sentences, flat clauses. No word classes, no phrases — a context-free grammar must commit to one reading, so that knowledge lives in later statistical layers.
  • POS tagger: greedy perceptron, 17 UPOS tags — EWT dev 91.9%, test 92.1% through beam re-decode plus fourteen gated correction rules.
  • Chunker: greedy phrase grouping over tags, with a fixed-phrase trie (as if, in spite of, because of).
  • Dependency parser: arc-eager + labels — UAS 83.9, LAS 80.2 (batch pass, not keystroke).
  • Lint: Vale-class findings from syntax (syntax.weasel, syntax.hedge, syntax.passive, syntax.nominalization, …), each with a 60-sentence eval.

Method

Bars before work. TDD corpus tests. EWT-majority oracle discipline. Rejections committed with forensics — distillation 0-for-5, char features 0-for-2, Brown clusters 0-for-1. See docs/workflow.md and ARCHITECTURE.md in the repo.
